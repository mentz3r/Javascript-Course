# Дорожная карта: Fullstack-разработчик, от нуля до Junior

Стек: JavaScript/TypeScript + React + Node.js. Расчёт на ~3 часа в день. Если у вас 2 часа в день, умножайте сроки на 1,4; если 4 часа, на 0,75.

**Итого:** 35 недель, около 700 часов, 61 блок, 353 пункта.

Как читать: каждый блок содержит пункты трёх типов. **изучить** (тема, которую нужно пройти), **сделать** (практика руками), **проверка** (объяснить без подсказки, это и есть закрепление). Блок закрыт, когда выполнены все обязательные пункты. Пункты «по желанию» можно пропустить.

## Этап 0. Фундамент и инструменты (2 нед., ~40 ч)

> Терминал, Git, как работает веб, DevTools, Node.js и npm.

### 0.1 Терминал и VS Code (~6 ч)

*Цель: работать в терминале и VS Code без мыши.*

- [ ] **изучить**: Навигация и файлы: pwd, ls, cd, mkdir, touch, cp, mv, rm
- [ ] **изучить**: Просмотр и поиск: cat, less, grep; абсолютные и относительные пути
- [ ] **изучить**: VS Code: открыть папку, поиск по проекту, горячие клавиши, терминал внутри редактора
- [ ] **сделать**: Создайте проект из терминала: папка, три файла, переименование и перенос между папками
- [ ] **сделать**: Поставьте расширения для HTML/CSS/JS: форматирование (Prettier) и Live Server
- [ ] **проверка**: Объясните разницу между абсолютным и относительным путём и что делает `rm -r`

### 0.2 Git и GitHub (~14 ч)

*Цель: вести проект в Git и работать через ветки и pull request.*

- [ ] **изучить**: Модель Git: рабочая папка, индекс, коммит; `init`, `status`, `add`, `commit`, `log`, `diff`
- [ ] **изучить**: Ветки: `branch`, `switch`, `merge`; что такое конфликт слияния и как его разрешить
- [ ] **изучить**: GitHub: remote, `push`, `pull`, `clone`, pull request
- [ ] **изучить**: `.gitignore` и понятные сообщения коммитов (`feat:`, `fix:`)
- [ ] **сделать**: Заведите репозиторий для учебных проектов и залейте его на GitHub
- [ ] **сделать**: Оформите 2–3 адаптивные страницы своей CSS-вёрстки: каждая в своей ветке и в своём pull request, даже если работаете одни
- [ ] **сделать**: Устройте конфликт слияния нарочно и разрешите его вручную
- [ ] **проверка**: Пройдите цепочку «ветка, коммит, push, pull request, merge» без подсказок

### 0.3 Как работает веб и HTTP (~12 ч)

*Цель: понимать, как браузер и сервер обмениваются данными.*

- [ ] **изучить**: Клиент и сервер, запрос и ответ; что происходит после ввода адреса в браузере (DNS, соединение, запрос, ответ, отрисовка)
- [ ] **изучить**: HTTP: методы (GET, POST, PUT, PATCH, DELETE), заголовки, тело запроса
- [ ] **изучить**: Статус-коды: 2xx, 3xx, 4xx, 5xx (200, 201, 301, 400, 401, 403, 404, 500)
- [ ] **изучить**: DNS, IP-адреса, порты, HTTPS в общих чертах
- [ ] **сделать**: Откройте любой популярный сайт и опишите в README, какие запросы он делает при загрузке (тип, метод, статус)
- [ ] **проверка**: Объясните разницу между GET и POST и между 200, 404 и 500
- [ ] **проверка**: Расскажите своими словами, что происходит после ввода адреса и нажатия Enter

### 0.4 DevTools браузера (~4 ч)

*Цель: использовать DevTools для поиска ошибок и запросов.*

- [ ] **изучить**: Elements: смотреть и менять DOM и стили на лету
- [ ] **изучить**: Console: логи, ошибки, выполнение кода
- [ ] **изучить**: Network: список запросов, фильтры, заголовки, ответ, время
- [ ] **сделать**: Найдите в Network запрос с данными (JSON) на любом сайте и прочитайте его ответ
- [ ] **сделать**: Найдите на любой странице ошибку в Console и объясните её текст
- [ ] **проверка**: Объясните, чем Elements, Console и Network отличаются и когда нужна каждая вкладка

### 0.5 Node.js и npm (~4 ч)

*Цель: установить Node.js и работать с пакетами npm.*

- [ ] **изучить**: Что такое Node.js и чем он отличается от JavaScript в браузере
- [ ] **изучить**: Установка LTS-версии, проверка `node -v` и `npm -v`
- [ ] **изучить**: npm: `init`, `install`, `package.json`, `node_modules`, скрипты
- [ ] **сделать**: Создайте проект через `npm init`, установите один пакет и запустите JS-файл командой `node`
- [ ] **проверка**: Объясните, что лежит в `package.json` и почему `node_modules` не коммитят

## Этап 1. JavaScript и современный CSS (6 нед., ~120 ч)

> Язык, DOM, асинхронность, работа с API, Flexbox, Grid, адаптивность.

### 1.1 Основы JS: значения, переменные, условия (~10 ч)

*Цель: свободно писать условия и понимать типичные ошибки.*

- [+] **изучить**: Числа, строки, шаблонные строки, `console.log`
- [+] **изучить**: `let` и `const`: что const запрещает и чего не запрещает; неявные глобальные переменные
- [+] **изучить**: Типы: `typeof`, `null` и `undefined`, `NaN`
- [+] **изучить**: Сравнения: `===` и `==`, особенности сравнения строк и чисел
- [+] **изучить**: Boolean: шесть ложных значений, `&&`, `||`, `!`, `??`, `?.`, тернарный оператор, приоритет операторов
- [+] **сделать**: Решите 10 небольших задач на условия (проверка пароля, расчёт налога, форматирование числа) и проверьте каждую на трёх входах: обычный, пустой, мусорный
- [+] **проверка**: Объясните, когда `||` даёт неверный результат (`0`, `''`) и чем его заменить
- [+] **проверка**: Отличайте ReferenceError от TypeError по тексту ошибки

### 1.2 Функции (~8 ч)

*Цель: писать функции, которые возвращают значения и не ломаются на мусорных данных.*

- [+] **изучить**: Параметры и аргументы, `return`; функция без `return` возвращает `undefined`
- [+] **изучить**: Область видимости: глобальная, внутри функции, `let` в блоке
- [+] **изучить**: Функции как значения: передача функции в функцию, стрелочные функции
- [+] **изучить**: Ранний `return` и функции, которые считают и возвращают значение, а не выводят его на экран
- [+] **сделать**: Напишите 8 функций, которые возвращают значение (например, `getMax`, `formatCount`)
- [+] **сделать**: Добавьте к каждой проверку на пустой и мусорный вход
- [+] **проверка**: Объясните разницу между «функция вывела на экран» и «функция вернула значение»
- [+] **проверка**: Объясните, почему переменная, созданная внутри функции, недоступна снаружи

### 1.3 Объекты и массивы (~12 ч)

*Цель: понимать ссылки и уверенно работать с объектами, массивами и циклами.*

- [+] **изучить**: Объекты: свойства, методы, доступ через точку и скобки, вложенные объекты
- [+] **изучить**: Ссылки: что копируется при `const b = a` и при передаче объекта в функцию (изменить поле или заменить объект)
- [+] **изучить**: Деструктуризация и spread (`...`) для массивов и объектов
- [+] **изучить**: Массивы: `push`, `splice`, `length`, индексы, `includes`, `indexOf`
- [+] **изучить**: Циклы: `for`, `for...of`, `while`, `break` и `continue`
- [+] **сделать**: Напишите функцию, которая меняет объект на месте, и функцию, которая возвращает новый объект; сравните поведение
- [+] **сделать**: Решите 8 задач на массивы и циклы (сумма, максимум, подсчёт, разворот)
- [+] **проверка**: Предскажите вывод кода с `splice`, `push` и копией массива до запуска
- [+] **проверка**: Объясните, почему `{ n: 1 } === { n: 1 }` равно `false`

### 1.4 Методы массивов (~10 ч)

*Цель: заменять циклы методами массивов.*

- [+] **изучить**: `forEach`, `map`, `filter`, `find`, `findIndex`, `some`, `every`

- [ ] **проверка**: Объясните, чем `map` отличается от `forEach` и что вернёт `filter`
- [+] **проверка**: Без подсказок напишите: оставить из списка только выполненные и посчитать их

### 1.5 DOM и события (~12 ч)

*Цель: строить интерфейс из данных и реагировать на действия пользователя.*

- [ ] **изучить**: `querySelector`, `querySelectorAll`, `innerHTML`, `textContent`, `value`, `classList`, `style`
- [ ] **изучить**: События: `onclick`, `onkeydown`, `addEventListener`, объект `event`

### 1.7 Замыкания, this и прототипы (~10 ч)

*Цель: собрать три проекта, которые показывают разные навыки.*

- [ ] **изучить**: Что должно быть в портфолио: три разных проекта вместо десяти одинаковых to-do
- [ ] **сделать**: Проект 1: полноценный fullstack-продукт (авторизация, роли, БД, тесты, деплой)
- [ ] **сделать**: Проект 2: интеграция внешнего сервиса (платёжка в тестовом режиме, загрузка файлов, Telegram-бот или OAuth)
- [ ] **сделать**: Проект 3: реальная работа для реального человека (сайт для знакомого бизнеса, репетитора, волонтёров)
- [ ] **сделать**: Для каждого проекта: ссылка на деплой, скриншоты или GIF, стек и объяснение, почему приняты ключевые решения
- [ ] **проверка**: По каждому проекту подготовьте рассказ на 3 минуты

### 6.2 Оформление GitHub (~8 ч)

*Цель: сделать профиль GitHub понятным за минуту.*

- [ ] **сделать**: Профильный README (репозиторий с именем аккаунта): кто вы, стек, ссылки на лучшие проекты, контакты
- [ ] **сделать**: Закрепите 3–4 лучших репозитория, остальные приведите в порядок или скройте
- [ ] **сделать**: В каждом проекте: README, скриншот, инструкция запуска, список функций, `.env.example`
- [ ] **сделать**: Приведите историю коммитов в порядок: осмысленные сообщения, ветки и pull request
- [ ] **проверка**: Попросите знакомого открыть ваш профиль и за минуту рассказать, чем вы занимаетесь

### 6.3 Фриланс (~14 ч)

*Цель: получить первые заказы и отзывы.*

- [ ] **изучить**: Площадки: Upwork, Kwork, FL.ru, Habr Freelance, Telegram-чаты по вашей теме
- [ ] **изучить**: Позиционирование: конкретная специализация («React-лендинги и админки»), а не «делаю всё»
- [ ] **изучить**: Процесс: ТЗ, сроки, правки, приёмка; объём работ письменно; хотя бы частичная предоплата
- [ ] **сделать**: Оформите профиль на одной площадке
- [ ] **сделать**: Откликнитесь на 10 небольших заказов и сохраните тексты откликов
- [ ] **сделать**: Выполните первый заказ и попросите отзыв
- [ ] **проверка**: Объясните, как вы фиксируете объём работ и что делаете, когда просят «ещё одну маленькую правку»

### 6.4 Алгоритмы для собеседований (~10 ч)

*Цель: решать задачи уровня easy для собеседований.*

- [ ] **изучить**: Массивы, строки, хеш-таблицы (объекты и Map), два указателя
- [ ] **сделать**: Решайте 2–3 задачи в неделю уровня easy (LeetCode)
- [ ] **сделать**: Разберите 10 решённых задач и назовите сложность каждой
- [ ] **проверка**: Объясните на примере, чем O(n) отличается от O(n²)

### 6.5 Английский для работы (~6 ч)

*Цель: читать документацию на английском.*

- [ ] **изучить**: Чтение документации (MDN, react.dev) без переводчика
- [ ] **изучить**: Базовые фразы для переписки с заказчиком и для issues
- [ ] **сделать**: Прочитайте три раздела документации на английском и перескажите
- [ ] **сделать**: Напишите README одного проекта на английском
- [ ] **проверка**: Найдите решение ошибки в англоязычной документации или на Stack Overflow, не пользуясь переводчиком

### 6.6 Подготовка к собеседованиям (~14 ч)

*Цель: уверенно отвечать на технические вопросы для джунов.*

- [ ] **изучить**: JS/TS: замыкания, event loop, `this`, промисы, `let`, `const` и `var`, типы в TS
- [ ] **изучить**: React: хуки, зачем `key`, `useMemo` и `useCallback`, управляемые и неуправляемые компоненты
- [ ] **изучить**: Backend и БД: REST, JWT против сессий, `JOIN`, индексы, транзакции
- [ ] **изучить**: Общее: HTTP, Git, что происходит при вводе URL в браузер
- [ ] **сделать**: Проведите 2–3 пробных интервью с друзьями или на платформах для mock-интервью
- [ ] **сделать**: Подготовьте двухминутный рассказ о себе
- [ ] **проверка**: Ответьте вслух на 20 вопросов из списка выше без подсказок

### 6.7 Резюме и отклики (~8 ч)

*Цель: отправлять отклики системно.*

- [ ] **сделать**: Резюме на одну страницу: стек, проекты со ссылками, без воды
- [ ] **сделать**: Шаблон сопроводительного письма, который вы адаптируете под каждую вакансию
- [ ] **сделать**: Отправляйте 20–30 откликов в неделю и ведите таблицу откликов
- [ ] **проверка**: Разберите каждый отказ или молчание: что можно улучшить в резюме или портфолио

## Правила, которые сэкономят месяцы

1. Пропорция 30/70: 30% времени на теорию, 70% на код своими руками. «Туториальный ад» главная причина застревания.
2. Не копируйте код из видео. Досмотрели урок, закройте его и повторите то же самое с нуля.
3. ИИ-ассистентов используйте как репетитора, а не как автора кода. Просите объяснять и разбирать ошибки, но пишите решения сами.
4. Ведите короткий журнал прогресса: что сделал, что не понял. Через месяц вы увидите рост, а это помогает не бросить.
5. Не переходите на следующий этап, пока не закрыли чек-лист, но и не застревайте: если этап затянулся в полтора раза, двигайтесь дальше и вернитесь к пробелам через практику.
